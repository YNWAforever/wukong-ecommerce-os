# 酒類自動查證與完整商品頁設計

基準：`3ca5b99520e056bda99c0efbe87192e619026f04`

## 1. 目標與已確認決策

服務葡萄酒、烈酒及清酒。上傳商品照片後，自動確認酒款、以 Tavily 搜尋查證，並生成英文及香港繁體中文完整商品頁。人工主要處理身分疑點、重大衝突及最後審核。

採用分階段查證，資料不足時才進入有限的深度搜尋。完整內容包含名稱、賣點、介紹、風味、配餐、飲用建議、酒莊／品牌背景及 SEO；沒有可靠資料的可選段落省略。

本設計不啟用自動發布，不更改 SHOPLINE 發布關閉狀態；不擴展成通用商品平台，不建立無限循環研究代理，不包含商品白底圖重製。

成功的定義是：商品身分匹配正確、每項事實可追溯、商戶修正不流失、搜尋失敗可恢復，而且操作人員能完成審核。文案更長或模型自評更高不等於準確性改善。

## 2. 現有系統與需要改進之處

目前正式模型為 OpenCode Go `deepseek-v4.1-flash`。現有系統已有不可變執行快照、Queue、實體呼叫紀錄、預算預留、人工欄位鎖定、版本及網站證據建議／採用機制。

主要程式邊界：

- `packages/ai/src/prompts.ts`：辨識與生成提示詞。
- `packages/ai/src/fact-grounding-rules.ts`：欄位來源與正規化規則。
- `apps/worker/src/listing-operation-pipeline.ts`、`operation-ai.ts`：持久化執行及呼叫記帳。
- `apps/web/lib/listing-enrichment-service.ts`：網站資料取得、身分匹配及建議採用。
- `packages/core/src/listing-schema.ts`：商品及審核內容契約。
- `packages/core/src/workspace-policy.ts`：商戶政策與允許來源。

現有生成門檻主要依賴 producer，不能當成精確酒款匹配；現有補充流程要求手填英文標題、URL 及 `Market variant:` 備註。新流程增加結構化身分及自動找來源，沿用證據、修正保護與版本機制。

網站／Tavily 證據應擴充為明確的來源型別；不得偽裝成照片 asset ID 或商戶 note 來通過舊驗證。

## 3. 使用者流程

### 3.1 上傳

拖放正面、背標及包裝照片，可補商戶資料。SKU、價格、庫存可稍後填。已完成的上傳保留；重試只上傳未完成檔案。

按「辨識並建立商品」建立持久化操作。伺服器先確認身分權限、版本、可用供應商和預算，才派送 Queue。

### 3.2 自動處理

流程：照片辨識 → 商品候選匹配 → 搜尋查證 → 內容生成 → 品質檢查 → 審核。

顯示當前階段、已完成結果及需要使用者處理的具體問題；不顯示虛構百分比或保證完成時間。離開頁面不取消背景工作。

遇到無法區分的候選酒款，顯示名稱、年份、規格、来源與差異，讓使用者選擇或補拍。選擇會寫入新的輸入版本，再建立新操作。

### 3.3 審核

- 主要區域：可編輯的中英商品頁，按段落組織。
- 待處理事項：身分疑點、重大衝突、缺少的商戶必填資料。
- 可展開來源面板：欄位／段落連至照片原文、網頁摘錄、取得時間及來源。
- 明確區分「重新查證」「重新生成文案」「重新生成此段」。
- 人工修改預設鎖定；新建議呈現差異，使用者明確採用才覆蓋。
- 可選資料未找到顯示為資訊提示，不計入阻擋審核的待處理數。
- 通過審核後仍走現有輸出／發布門檻；不把 in_review 當成已可發布。

## 4. 商品身分與酒類資料

新增版本化 `ProductIdentity`，與展示標題分開保存：

- 類別、品牌／生產者、原文酒款名稱、已確認別名。
- 酒款系列或 cuvée、年份狀態、容量、包裝數量、市場版本。
- 條碼（照片清晰時）、酒精濃度及各值的來源引用。
- 欄位狀態：已讀取、確定正規化、未知、明確不適用、衝突。
- 身分狀態：候選、已匹配、需要確認；判斷理由及不匹配維度。

葡萄酒包含產區／法定產區、葡萄品種、年份；烈酒包含酒種、年齡聲明、桶型與批次；清酒包含酒造、等級、米種及精米步合。酒齡、年份與釀造年度不可混為一談。新增類別欄位放在有版本的類別資料中，不強迫填進既有 grapeVarieties 或 vintage。

未看到年份是未知，不等於 NV；無年份酒須有明確標示或匹配資料。未知市場版本不再阻擋所有查詢；只允許品牌背景等不依賴市場版本的資料，規格仍須匹配後採用。

自動匹配需要生產者／品牌及實際酒款名稱，且所有已知年份、容量、系列、批次等限制均相容。只有品牌名、Tavily 排名分數、模糊字串相似度或模型自信分數不足以確認酒款。多個未能區分的候選不自動挑第一筆。

## 5. Tavily 搜尋與來源政策

### 5.1 搜尋策略

由已抽取的身分生成查詢，包含精確酒款名稱及已知年份／規格。市場資料不明時，不自行補上 HK 作為已確認事實。

每次完整操作最多：

1. 一次基本搜尋，找官方酒款及身分資料。
2. 一次基本搜尋，只補重要缺口或交叉核對。
3. 一次進階搜尋，僅在前兩步仍有重要缺口或可解決的衝突時使用。

設定明確的搜尋深度，關閉 `auto_parameters`；每次最多 5 個結果，跨搜尋按正規 URL 去重。只缺品牌故事、評分或可選段落，不觸發深度搜尋。

來源優先序：酒莊／酒廠／品牌的匹配資料 → 官方進口商／代理 → 有來源責任的專業商戶／專業酒類出版物。依工作區允許網域政策縮小範圍；無可用來源時不繞過政策。

官方身分不能只靠搜尋排名或網域名稱看起來像官方；須保存網域與品牌的可核實關聯，無法確認時降級處理。相同文案的轉載不計成獨立佐證。

### 5.2 內容取得

搜尋摘要作為線索。採用的事實必須引用足夠的來源摘錄；年份、規格、評分及獎項不得只靠搜尋結果標題推斷。

優先沿用安全的公開網頁取得流程。對適合的候選，允許最多一次 Tavily basic Extract 批次，最多 5 個 URL；不使用 Crawl、Map 或 Research。

每項證據保存 URL、標題、網域、來源類型、適用身分、取得時間、原文摘錄、位置及內容雜湊。沒有取得全文時，明確標示實際取得的是摘要；不得宣稱已查閱全文。

保留公開 HTTPS、重導向檢查、內網位址阻擋、robots 政策及下載大小限制。直接抓取被拒絕或 robots 禁止時，不以 Tavily Extract 作為繞過途徑。

搜尋請求只傳查證必要的公開酒款身分，不傳原始照片、私有讀取 URL、商戶備註、價格、庫存或內部 SKU。網頁內容視為不可信資料，不能更改系統規則、執行工具或索取憑證。

## 6. 自動採用與衝突規則

| 類型                       | 採用規則                                                     |
| -------------------------- | ------------------------------------------------------------ |
| 年份、容量、ABV、包裝      | 清晰瓶標優先；補充資料須符合相同酒款與適用版本               |
| 產區、葡萄品種、釀造、熟成 | 優先匹配官方資料；年份相關資訊須核對年份                     |
| 品牌背景                   | 可使用品牌層級資料，不投射成該瓶酒的特徵                     |
| 風味                       | 必須有匹配酒款支持；不能把相似款或其他年份當成該瓶的已知描述 |
| 配餐、飲用建議             | 依已確認風格產生，明確表達為建議，保留推導依據               |
| 評分、獎項、適飲期         | 可核實來源、評分機構／獎項及適用酒款年份；不足就省略         |
| 價格、庫存、內部 SKU       | 僅採商戶資料                                                 |

一個精確匹配、身分可信的官方來源可支持其明確聲明。沒有官方資料時，核心補充事實需兩個獨立可靠來源一致；否則保持未知。專屬評分應以評分機構或可核實的原始評分紀錄支持。

人工值不被自動覆蓋；發現矛盾時標記供審核。照片與可信匹配官方資料若有重大矛盾，不用多數票覆蓋照片，也不把低可信搜尋噪音升級成阻擋。

業務上停止完整生成的條件：商品身分仍不明，或年份／規格等重大衝突經有限查證仍未解決。保留可用的辨識資料與部分結果，要求補拍／選擇／修正。

非必要資料缺失時繼續。未解決的補充描述省略，不能靠同義改寫掩飾欠缺證據。

## 7. 提示詞與完整商品頁

四種職責分開版本化，按酒類套用欄位及寫作指引：

1. 辨識：抽取身分、類別事實及可見原文；不使用世界知識補造照片事實。
2. 查證：輸出候選匹配、可採用的逐項主張、來源引用、未知與衝突理由。
3. 寫作：只使用已採用事實／建議、商戶語氣和鎖定內容，生成中英段落。
4. 檢查：找出文意偏離、翻譯不一致與缺少支持的敘述，回傳定位明確的問題。

提示詞、模型、輸出契約與規則版本固定在操作快照。升級提示詞不能改寫既有接受操作；新版本另建操作。

內容結構：localized 名稱、賣點、介紹、風味、配餐、飲用建議、品牌背景、SEO title／description、tags。段落附事實／建議引用。沒有支持的可選段落不輸出標題或佔位內容。

既有 description 由段落結構確定性組合，以相容既有預覽、匯出與下游契約。舊版自由文字內容仍可讀取；人工整段編輯若無法安全定位，整段標記人工鎖定，不能猜測段落對應後覆蓋。

語氣採清楚、具體、節制的香港繁體中文與自然英文。避免空泛頂級形容詞、未經支持的稀有性／收藏價值／健康宣稱；翻譯不新增事實。原有商戶 tone 與 claim policy 持續生效。

數值、單位換算、年份、來源引用、保護欄位及必要格式用程式檢查。模型檢查輔助文意，不得推翻確定性驗證或把自身評分當成已校準信心。

## 8. 執行邊界、資料與恢復

### 8.1 模組責任

- 核心領域：身分、來源適用性、主張狀態、衝突分類、內容段落及驗證規則。
- Tavily adapter：固定供應商端點、輸入／輸出界限、使用量與安全診斷，不決定主張真偽。
- 資料庫：版本化身分／證據／段落、呼叫紀錄、分階段結果及預算預留。
- Worker：編排持久化階段及供應商呼叫。
- Web：驗證權限、接受操作、顯示進度、處理確認與審核；不持有 Tavily 金鑰。

沿用現有 listing、input revision、run、version、outbox、claim support 及審核交易邊界。必要的 schema 擴充使用向後相容 migration；禁止舊網頁／新 Worker 在未完成相容性檢查時接受新操作。

### 8.2 建議的持久化階段

`extraction → search_basic → verification → search_deep_if_needed → verification_if_needed → generation → quality_check → commit_candidate`

每個階段保存輸入 digest、狀態、輸出版本、來源／規則 digest 及供應商呼叫 ID。網路呼叫前先提交 started 記錄；交易中不等待外部請求。

取消、輸入修改、人工欄位修改與結果採用沿用列鎖及版本檢查。舊結果可查看，但不得覆蓋新輸入或被誤顯示為目前版本。人工修改使相關生成／驗證失效；改變身分則使依賴該身分的搜尋證據與主張失效。

### 8.3 重用與重試

相同工作區、身分、來源政策與規則版本下，成功證據可在 7 天內重用。此期限是快取有效期，不保證來源仍正確；保留取得時間並提供主動重新查證。跨租戶不共享私有證據快取。

段落重生只使用目前有效且已採用的證據，不額外搜尋。重試建立新的不可變操作，明確引用父操作；只重用依賴完全相符的已完成階段。外部費用未知的呼叫不自動重放，使用者明確重試需另作預算預留。

搜尋配額不足／暫時不可用且照片身分已確認時，可生成僅使用已知資料的草稿，標記補充未完成。身分不足則 needs_info；模型認證失效或必要服務失敗則顯示具體恢復操作，保留已上傳及已完成資料。

不因 Queue 重送、瀏覽器重新整理或雙擊而新增付費呼叫。SDK 自動重試關閉；schema 修復只允許預算內一次，修復不得改掉已確認的身分或商戶值。

## 9. 成本與操作界限

以下為本版可檢查的初始設計預設；啟用新供應商的實際配額另有部署門檻：

- 最多 2 次 basic Search + 1 次 advanced Search：最多 4 search credits。
- 最多 1 次 basic Extract 批次、5 URL：額外預留 1 credit。
- 因此 Tavily 每次完整操作預留最多 5 credits；沒使用的部分釋放。實際依官方回應及帳戶用量記錄，回應不明維持未知，不當成免費。
- 每次搜尋／擷取逾時 30 秒，限制總回應 8 MiB，供模型使用的每來源文字上限 16,000 字元；截斷必須記錄，不能讓截斷後的內容偽裝成完整證據。
- Go 最多 5 次邏輯呼叫：辨識、第一輪查證、必要的第二輪查證、生成、品質檢查。每次最多一次 schema 修復，故完整操作最多 10 次實體呼叫。
- Go 每次輸出上限初始為 4096 tokens。按目前已審閱的全 context／尖峰價格，10 次最保守預留為 US$3.194880；不得沿用目前四次呼叫的 US$1.277952 預留。
- 段落重生最多生成、品質檢查各一次邏輯呼叫（含各一次修復共 4 次實體呼叫），不預留未使用的搜尋階段。
- 最長背景執行期限初始為 15 分鐘，跨 Queue 分段執行；達到期限停止新增呼叫，保留紀錄供明確重試。無法中止的在途請求仍可能產生費用，記帳保持未知直至可確認。

Go 與 Tavily 使用不同計量及獨立配額；介面不把 Tavily credits 當成 Go 的 USD 成本。既有 Go 工作區 US$10 累計估算上限與未知預留不自動增加或清除。若剩餘額不足以預留新操作，在付費呼叫前阻止接受。

Tavily 金鑰僅存 Worker secret。缺少金鑰或未批准配額時，不啟用自動搜尋；現有無搜尋的功能維持可用。供應商付費方案、自動加值及額外扣款不隨部署自動啟用。

官方參考（2026-09-16 查閱）：

- [Tavily credits 與費率](https://docs.tavily.com/documentation/api-credits)：basic Search 1 credit、advanced Search 2 credits、basic Extract 每 5 個成功 URL 1 credit。
- [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)：搜尋參數、來源結果及使用量。
- [OpenCode Go](https://opencode.ai/docs/go/)：Go 模型與用量；目前 Go 啟用證據另見既有 activation 文件及本機 runtime evidence。

## 10. 品質與驗收

先建立固定、可重播的 60 個標註案例：葡萄酒 30、烈酒 15、清酒 15；同一照片及凍結來源快照供改版前後比較。需涵蓋相似酒款、不同年份、NV、批次差異、模糊背標、單位換算、來源衝突及惡意網頁指令；上述邊界可交疊於案例。

案例需有人工標註的正確身分、可支持事實、不可支持主張及預期是否需確認。程式測試可使用合成內容；商戶真實照片僅在授權範圍使用，不能將私有資料放入公開 repository。

發布門檻是待驗證目標，不是目前結果：

- 固定集不得自動確認錯誤商品、跨年份評分／獎項，或覆蓋商戶鎖定值。
- 主張的來源引用可解析且實際支持主張；測試集不得有捏造商戶價格／庫存／SKU。
- 核心欄位正確率不低於基準；對固定集可解答的缺失欄位，至少修正基準錯誤／缺漏的 20%，且不能靠全部 abstain 達成。
- 報告身分自動確認覆蓋率、錯誤確認率、欄位正確率、可驗證主張比例、人工修正次數及生成段落完整率；缺失與不適用分開統計。
- 報告完整流程 p50／p95 時間、Go tokens／估算用量、Tavily credits。首版效能目標 p95 不超過 180 秒；是否達成須以實際驗證為準，不能宣稱為保證。
