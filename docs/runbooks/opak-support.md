# Opak 支援與恢復

適用於每日維護。使用者保留畫面支援編號、工作區、時間及受影響商品／批次／檔案參照；不要在公開訊息貼客戶內容、prompt、模型輸出、帳密或商戶原檔。

| 畫面情況                   | 員工下一步                             | 支援核對                                                  |
| -------------------------- | -------------------------------------- | --------------------------------------------------------- |
| 可重試的已知失敗           | 按「只重試失敗」；保留原批次           | 確認相同選欄、版本及來源，成功項未重播                    |
| 待補資料／身份矛盾         | 補來源或人工更正後重新預覽             | 年份、容量、包裝、變體及來源綁定；不猜資料                |
| 內容／来源／確認已變       | 開啟目前商品、重新確認及審核           | 較新人手版本、來源及批准 freshness                        |
| 成本或執行結果未知         | 停止重试該項，按執行編號核對           | 保留 reservation、未知成本及外部結果；未證明失敗前不重放  |
| 某列不能讀取               | 按該列支援編號回報，其他可讀列繼續     | 安全 row/stage 分類；受影響列不能批准／匯出               |
| 整頁資料不能讀取           | 保留支援編號，重試一次或聯絡管理員     | 全 DB／權限／schema 問題必須是錯誤，不能當作空列表        |
| 權限改變／無法進入管理     | 檢查帳戶及目前工作區，聯絡顯示的管理員 | 當前 server session／membership／role；不靠瀏覽器角色放行 |
| 未存設定儲存失敗           | 留下並修正／重試，勿切工作區           | CAS 衝突及表單原內容；舊值不覆寫新設定                    |
| 商戶部分拒絕               | 按固定檔案逐件回填，僅修拒絕項         | 原 artifact／attempt／version 與修復 lineage 分開         |
| 檔案下載／新資料核對有問題 | 暫停該次交付及擴量                     | 確切 artifact hash、逐 cell 差異、商戶新匯出來源及時間    |

工程支援按 request ID 及安全 stage 定位；一般 logs 只記分類、狀態、數量及不透明參照。需要內容時，由授權支援在私人證據位置查看，不把內容加進一般記錄。部署、有效 DB 角色、migration、web／worker 版本按 [release acceptance](opak-release-acceptance.md) 核對。

「正常」「阻塞」「未驗證」有不同意義。設定存在不等於 provider／SHOPLINE 已連通；儲存可用、已觀察的 worker 或成本統計不等於正式交付成功。Cloud preview／正式問題重現仍未完成時，如實保留 blocker。

基礎設施回復以停新工作及回復相容程式為主，保留來源、版本、審核、回報、reservation 及未知结果。商戶內容恢復是另一次經授權的人工操作，須保留原始商戶檔、取得新匯出核對及確認確切恢復範圍；不得自動把舊整列重新匯入。
