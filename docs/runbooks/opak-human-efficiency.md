# Opak UC30 human timing record

UC30 requires an operator's measured completion time for20items and an acceptance rate. Automated browser timings and fake-AI output do not establish employee minutes or commercial AI quality. This procedure records the missing human evidence; the blank template is not a passed result.

Use [the20-row CSV template](./opak-human-efficiency-template.csv). Save completed records and the private case-to-product mapping outside Git. Public evidence may contain aggregate seconds/counts, dated source/deployment identifiers and anonymous case labels only. Keep customer content, employee identity, credentials, prompts and model responses private.

## Prepare comparable work

1. Name the operator privately and select the same20authorized products for both workflows. Record the exact source/version/content-gap snapshot and protected fields before work. Use isolated synthetic staging unless a separate merchant pilot has been authorized.
2. Define the accepted finish: selected content fields completed, human review recorded, protected fields unchanged, and result reconciliation complete. Use the same checklist in both workflows. Do not count a preview, generated candidate or unknown delivery as finished.
3. Run the existing manual workflow and Wukong workflow from equivalent retained starting snapshots. Keep an independent reviewer and equivalent source access. Record order/training and any interrupted case. Do not overwrite approved history or fabricate a baseline from already completed products.
4. Confirm candidate Web/Worker/DB identifiers, current authorized provider/budget flags and actual execution mode. Fake/mock results must be labelled as workflow evidence. Paid-model quality acceptance and the first real SHOPLINE write remain separately gated.

## Fill one row per case

Measure active operator seconds separately from waiting seconds in both workflows. Include finding the product, checking sources, editing, reviewing and reconciling results. Record0only when that activity was actually observed to take zero; leave missing values blank.

`accepted_without_edit` is `true` only after review accepted the result without editing selected content. Record the actual edited-field count, hard-fail count, protected-field drift and reconciliation result. `outcome` becomes `complete` only when the defined finish is met; use `incomplete` or `interrupted` otherwise. Missing/unknown results remain incomplete, even if the request returned200.

## Report and decide

Report observed totals/medians and completed counts for both workflows, wait seconds separately, accepted-without-edit count/denominator and edited fields per completed item. Compare time only for genuinely matched completed cases and disclose exclusions. With fewer than20matched completed cases, retain UC30's human gate as incomplete; do not report a20-item saving percentage.

Any unresolved hard failure, protected-field drift, unknown cost/identity/delivery or stale approval stops merchant expansion. A human timing record does not authorize paid AI, production changes or the merchant5→20→100 rollout.
