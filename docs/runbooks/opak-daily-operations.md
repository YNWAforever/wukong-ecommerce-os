# Opak 每日商品維護

本手冊說明已實作的操作；正式站版本、帳戶及商戶權限須先按 [release acceptance](opak-release-acceptance.md) 核對。本地合成驗證不能代替商戶接受結果。

## 開始一天

1. 登入後確認帳戶、目前工作區及角色。切換工作區前先處理未儲存內容；選「留下」或儲存失敗時，原工作區仍保持有效。
2. 開啟商品中心，以 SKU、名稱、來源或責任人找商品。SKU 前置零有意義。搜尋、篩選及頁碼保留在網址；返回列表會恢復該次選取及位置。
3. 參考資料只提供證據。維護已有 SHOPLINE 商品，須由管理員設定正確商店，再上傳實際維護匯出檔、填寫其香港時間及確認來源。來源 ID 建立匹配；年份、容量、包裝或變體矛盾須先處理，不能按名稱猜配。
4. 相同檔案重播保留原來源及時間，不會刷新批准。新來源或內容會使舊確認／批准失效。保留原檔於商戶批准的私人證據位置。

## 填寫及選欄位

先看目前已儲存內容及待確認事項。人工更正後儲存，可鎖定重要值；AI 舊結果不能覆寫較新的人手版本。資料不足時留待補資料，不猜年份、750ml、酒精度、包裝數量、評分或獎項。

AI 維護及 Bulk Update 內容欄位只可選：

| 欄位          | English label           |
| ------------- | ----------------------- |
| 中文名稱      | Chinese name            |
| 英文摘要      | English summary         |
| 中文摘要      | Chinese summary         |
| 英文 SEO 標題 | English SEO title       |
| 中文 SEO 標題 | Chinese SEO title       |
| 英文 SEO 簡介 | English SEO description |
| 中文 SEO 簡介 | Chinese SEO description |
| SEO 關鍵字    | SEO keywords            |

價格、SKU、庫存、商店／商品 ID、英文名稱及未選欄位不可由這次 AI 內容操作修改。完整描述及圖片不在此八欄範圍。

跨頁選取後，先看預覽的商品數、欄位、阻塞項及成本範圍，再確認建立。預覽不會執行 AI。若另一同事改內容或來源，重新預覽；不能沿用舊選取的版本。

## 處理進度及交接

暫停阻止下一批開始；已接受的工作仍須等結果或核對。只重試已知且可重試的失敗，不能把成功、待補資料、較新版本或未知結果重新執行。未知成本保留供核對，不當作零。

指派責任人是工作交接。它不代表批准或上線。操作員可領取未指派／自己的工作及按可用操作交接；審核員或管理員處理需要更高權限的指派。離職或移除角色後，以當前權限為準。

品質頁的文案缺口、事實證據、人工核實及交付條件各有含義。統計待更新／失敗會明示；沒有文案缺口不代表事實正確。專名雙語相同可能合理。已知 AI 成本與未知成本分開，可按批次或保留執行編號聯絡支援。

## 審核及交付

1. 操作員儲存及交審；審核員逐件查看來源、目前版本及確認清單。低風險批量批准仍須每件合法確認；部分失敗逐件處理。
2. Bulk Update 初始不選欄位。選商品、選要改的欄、確認來源仍有效，再預覽「舊值 → 新值 → 來源」。處理阻塞後才產生 XLSX。
3. 下載的是該次固定檔案。「檔案已生成」尚未代表商店已改。首次真 SHOPLINE 寫入須另有明確確認；本手冊不授權寫入。
4. 商戶回報接受／拒絕後，在結果頁按確切檔案及版本逐件回填。更正回報會保留歷史。只修復拒絕項，重新審核／預覽；已接受項不混入修復檔。
5. 取得另一份新商戶匯出檔獨立核對；不能上傳自己產生的交付檔來證明已上線。供核對的檔案來源及時間仍屬人工聲明，不能冒稱已直接驗證商店。

真商戶 pilot 依次 5 → 20 → 100 件。每階段須完成所有結果核對、無硬性錯誤、無未解成本或身份問題，並取得書面進階決定。遇拒絕／未回報／未知結果時保持目前規模。見 [UAT rollout](opak-uat-rollout.md)。

## 結束一天

保留未完成項、責任人、支援編號及待核對結果；登出會先確認伺服器 session 已失效。登出失敗時保留目前工作並按畫面重試。商戶檔案、內容及截圖留在私人證據位置，不放入公開 issue／PR／一般記錄。
